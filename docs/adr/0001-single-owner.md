# В системе один Владелец

Регистрации и входа в сценарии нет, поэтому сервис работает как личный календарь одного Владельца, а не как платформа вроде Cal.com. В адресах нет имени Владельца (`/`, а не `/<user>/intro`), Типы встреч и записи не привязаны к пользователю, а разделы Владельца открыты любому, кто знает их адрес.

## Consequences

Чтобы позже поддержать нескольких Владельцев, придётся менять схему адресов, контракт API и модель данных. Это сознательно отложено, пока в задаче нет аутентификации.
